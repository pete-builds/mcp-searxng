# mcp-searxng: engineering review, November 2026

Scope: the code at v0.5.0, seven competing SearXNG MCP servers read at source
level, a reproducible benchmark, and the fixes that came out of it (branch
`review/2026-11-hardening`). Every number below comes from a command in
`bench/` or `tests/` and can be rerun; where something was not verified, it
says so.

## 1. Executive assessment

**Before this pass, the project was strong on security posture and weak where
its README put its weight.** Enforced bearer auth, a DNS-pinned SSRF guard that
re-validates every redirect, a hash-pinned lockfile and the per-search
`provenance` block are better than most of the field. But:

- `search_deep`'s headline feature, ranking by engine consensus, **made results
  worse**. On a gold-set benchmark its top 10 scored below SearXNG's own order
  (nDCG@10 0.427 against 0.492 on held-out queries).
- `read_url` had resource-exhaustion holes the serious competitors had closed:
  it downloaded whole bodies before checking the size cap, had no overall
  deadline, decoded PDFs as text, and blocked the shared event loop on DNS.
- The request spacing meant to protect engines did not hold under concurrency.
- Getting started took two systems and a hand edit to SearXNG's config, with no
  PyPI package and no registry listing.

**After it, the project is competitive in one clear niche: the self-hosted
research backend an agent can trust to say when its results are bad, and that
is safe to point at the open web.** It is not the most popular choice
(ihor-sokoliuk/mcp-searxng has about 1,400 stars, npm, Docker Hub and registry
listings) and not the most featureful (it reads no PDFs and calls no LLM). It
should not try to be either. Its case is honesty and safety, now backed by
measurements instead of claims.

## 2. Prior art

Read from source, not run: ihor-sokoliuk (TypeScript, about 1,400 stars),
TadMSTR, bumbaRasch, DasDigitaleMomentum/searxNcrawl, tisDDM, SecretiveShell,
jae-jae.

| | this project | ihor | bumbaRasch | TadMSTR | searxNcrawl |
|---|---|---|---|---|---|
| HTTP auth | required, refuses to start | opt-in | required off localhost | opt-in | none |
| Page-reader SSRF guard | pinned DNS, per-hop | per-hop, lookup hook | per-hop, lookup hook | partial (TOCTOU on some tiers) | none |
| Streamed size cap, binary refused | yes (this pass) | yes | yes | yes | unverified |
| Engine provenance on a successful search | yes, every call | only "degraded" on empty | `doctor` tool | no | consensus ordering |
| Cross-page dedup | canonical URL (this pass) | canonical URL | no | across LLM variants | normalized URL |
| Result ordering | measured (this pass) | SearXNG score | heuristic | FlashRank + recency | consensus first |
| Domain filter | include / exclude (this pass) | no | boost | `site`, block / boost | no |
| Deep research | multi-page, no LLM | pages 1 to 5 | iterative loop, optional LLM | LLM query expansion | crawls each result |
| PDF | no | yes | yes | yes | yes (Chromium) |
| Install | Docker, git `uvx` | npm, signed Docker | npm, Docker | npm, Docker | PyPI, `.mcpb` |
| Official MCP registry | not yet (`server.json` ready) | listed | listed | no | listed |

**Genuinely distinctive here:** provenance on every successful search (no one
else reports corroboration when results do come back), enforced auth together
with a pinned per-hop guard (only bumbaRasch matches both), and the person
and tech presets (none found elsewhere).

**Common, not distinctive:** standard SearXNG parameters, a streamable HTTP
transport, Readability or trafilatura extraction, surfacing
`unresponsive_engines`.

**Corrected by this review:** the README's "no other SearXNG MCP ships" holds
only for `search_person`. And one apparent gap was not real: competitors
unwrap IPv6 forms that embed an IPv4 address by hand, but Python's `is_global`
already rejects all of them on 3.11, 3.12 and 3.13 (tested). A regression test
now pins that.

## 3. Findings

Confirmed defects (each now has a test that fails on 0.5.0):

| # | Defect | Where (0.5.0) | Severity |
|---|---|---|---|
| D1 | Size cap checked after full download (test: 20 MB pulled to enforce 2 MB) | `clients/reader.py:108` | P0 |
| D2 | No wall-clock deadline; per-read timeout only | `clients/reader.py:42` | P0 |
| D3 | Blocking DNS on the event loop | `clients/ssrf.py:111` | P0 |
| D4 | Rate limiter not concurrency-safe (measured gaps 0.0 s) | `clients/searxng.py:48` | P0 |
| D5 | Raw httpx errors with the internal SearXNG URL, no fix hint | `server.py:170-323` | P0 |
| D6 | `max_results=-1` dropped the last result; `pages=0` blamed engines | `server.py:201`, `searxng.py:288` | P0 |
| D7 | `pages_fetched` echoed the request | `searxng.py:320` | P1 |
| D8 | PDFs and images returned as text (live: 2.1 M chars, 88% printable) | `reader.py:116` | P1 |
| D9 | Consensus ranking lowered relevance (benchmark) | `searxng.py:198` | P1 |
| D10 | `search_person` returned zero results when SearXNG was down | `searxng.py:388` | P1 |
| D11 | Queries and names logged at INFO | `searxng.py:244, 399` | P2 |

Risks noted, not changed:

- `StaticTokenVerifier` (FastMCP) looks tokens up in a dict rather than with a
  constant-time compare. Timing a hash lookup over a network is not practical;
  noted for pete-mcp-core, not acted on.
- No minimum token length is enforced. A one-character `MCP_AUTH_TOKEN` starts.
  Belongs in pete-mcp-core.
- Search results and pages are untrusted text reaching an agent. The tool
  descriptions now say so; no server can do more without rewriting content.
- `search_news`, `search_tech`, `search_images` and `search_videos` are thin
  presets over `search`. Collapsing them would shrink the manifest but break
  every caller, so they stay.

Checked and found sound: per-hop redirect validation with DNS pinning and SNI,
IPv6 address pinning (brackets correctly), CGNAT and Tailscale blocking,
fail-closed auth, the lockfile drift gate, the Trivy scan, the non-root image,
the session-leak-free healthcheck, and parameter docs (they do reach the
schema; only the text after `Args:` is cut from descriptions).

Benchmark headlines (`bench/README.md` has method, raw tables and limits):

- `search_deep` nDCG@10: 0.427 to 0.492 on 14 held-out queries (paired CI
  +0.010 to +0.122), 0.416 to 0.473 on the 24 tuning queries; Recall@50
  unchanged on both.
- Same-page duplicates in `search_deep`: 6 to 0 (3 pages), 5 to 0 (5 pages).
- Response size: about 19% smaller for identical results.
- Latency: unchanged (search median 0.98 s and 0.94 s; read_url A/B median
  0.102 s and 0.103 s). Eight concurrent searches now take 8.2 s instead of
  1.9 s because the spacing finally applies; `SEARXNG_MIN_INTERVAL=0` turns it off.
- Peak memory in the live run: 219 MB to 169 MB (one run).

Not verified: clients other than Claude Code and the FastMCP client; Docker
Desktop on macOS or Windows; any comparison of numbers with competing servers.

## 6. Adoption strategy

Win on one claim that is true and easy to check, not on feature count.

- **Lead with the demo.** `bench/demo.md` shows a live search coming back as
  one engine's filler and the server saying so. That is the whole pitch.
- **Make the first five minutes work.** The SearXNG-included quick start is
  tested in CI. After 0.6.0, the registry listing and (once pete-mcp-core is
  on PyPI) `uvx mcp-searxng` remove the remaining friction.
- **Be where people look:** the official MCP registry, punkpeye/awesome-mcp-servers,
  Glama (indexes GitHub), mcp.so and PulseMCP; SearXNG's own discussions and
  r/selfhosted, where SearXNG users already are. None of this has been
  submitted; each needs Pete's go-ahead.
- **Don't oversell.** No "best" or "fastest". Compare with other servers only
  on the same recording (roadmap 5). Say plainly what it does not do (PDF, LLM
  summaries) and point to who does.

## 7. Positioning: README introduction

> **Self-hosted web research for AI agents. No paid search API required.**
>
> An MCP server for your own SearXNG instance. It gives an agent web search, a
> multi-page research sweep, and a page reader, and it tells the agent when the
> results are not worth trusting.
>
> Self-hosted metasearch has one failure mode that matters more than any other:
> engines get blocked by IP, quietly, and SearXNG keeps answering with whatever
> one engine has left. Every search here returns a `provenance` block that says
> how many engines actually answered, and flags a degraded response in words.

This is now the top of `README.md`.
